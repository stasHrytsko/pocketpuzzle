# Pocket Puzzle на Unity — техническая основа

**Версия:** 0.1 · 2 ноября 2026. Заменяет PWA-архитектуру из `CONCEPT.md` §8 (старый текст оставлен там для истории).

## 1. Решения автора (2026-11-02)

- **Движок — Unity. Всё на Unity:** оболочка (комната, письма, конверт, архив) и сами игры, на C#.
- **Платформа MVP — нативные iOS и Android**, через сторы. PWA больше не цель.
- **Главная-«комната» — 2D-спрайты с параллаксом** (ТЗ — `design/ROOM-ART-BRIEF.md`).
- Следствие: правило «движки не переписываются» отменено. Движки игр **портируются** с TypeScript на C#.

## 2. Что из старых решений больше не действует

| Было | Стало |
|---|---|
| MVP — PWA, нативные приложения с v3 | Нативные iOS + Android с MVP |
| Игры — Vite/TS workspaces, оболочка импортирует их | Игры — C#-модули внутри одного Unity-проекта |
| На iOS уведомления только после «добавить на экран Домой» (экран ONB-07) | Обычные локальные уведомления; ONB-07 не нужен |
| На iPhone хаптики нет (Safari) | Хаптика есть на обеих платформах (§9) |
| Заставки PWA из манифеста и `apple-touch-startup-image` (прил. Г) | Заставка Unity / нативный launch screen (§8) |
| «Доступна новая версия» — обновление веб-кэша | Обновление через стор; баннер — только для контента (§7) |

Что **не меняется:** вся продуктовая логика, экраны из `design/SCREENS.md`, токены из `design/pocket-puzzle-tokens.json`, модель данных письма (`CONCEPT.md` §8), принципы §6.

## 4. Как переносим игры

1. **Движок — чистый C#** без `UnityEngine`: состояние, ходы, проверка победы, отмена. Это отдельная сборка (`.asmdef`) на игру, тестируется NUnit без запуска сцены.
2. **Уровни — один источник правды в `stazzi`.** Генераторы и солверы остаются на TS/Node (это офлайн-инструменты, переписывать не нужно). Добавляем в каждый `tools/` экспорт `levels.json` в общий формат; Unity читает только JSON.
3. **Проверка совпадения (golden tests).** Для каждой игры записываем в TS последовательности ходов и итоговые состояния (JSON), и тот же набор прогоняем в C#. Совпало — порт верный. Без этого порт не принимаем.
4. **UI игры — заново в Unity** по токенам и `componentStates` из JSON; поведение и тексты — из SPEC.md каждой игры.
5. **Контракт игры для оболочки:**

```csharp
public interface IPuzzleGame
{
    string GameId { get; }
    int LevelCount { get; }                      // из данных, не выдумывать
    void Begin(PuzzleRequest request);           // gameId, levelId, seed, source: Letter | Free
    event Action<PuzzleResult> Completed;        // levelId, elapsedSeconds, hintsUsed, undoCount
    event Action<PuzzleSnapshot> Exited;         // для «Продолжить» и восстановления после выгрузки
}
```

`elapsedSeconds` идёт на марку (время решения), `levelId` — в прогресс игры (задача из письма = следующий уровень, решение автора 2026-11-01).

## 5. Unity-проект

| Что | Выбор | Почему |
|---|---|---|
| Версия | Актуальная **Unity 6 LTS** на момент старта — уточнить номер | Долгая поддержка |
| Рендер | URP, 2D Renderer | Спрайты, параллакс, мягкий свет лампы без 3D |
| UI | **uGUI + TextMeshPro** | Предсказуемо на мобильных, много примеров; UI Toolkit — можно пересмотреть позже |
| Ввод | Input System | Свайп комнаты, тапы, жесты игр |
| Тексты | Unity Localization | Языки — открытый вопрос (SET-05) |
| Уведомления | `com.unity.mobile.notifications` | Локальные напоминания о письме |
| Контент | JSON в `StreamingAssets` (MVP); Addressables — если контент будет приходить без обновления в сторе | Всё локально, как решено для MVP |

## 6. Токены → Unity

- **Цвета** в JSON — sRGB hex. Проект в Linear color space; цвета задаются как sRGB (так их и вводят в инспекторе), спрайты UI импортируются с галкой sRGB. Приёмка: сверить на устройстве с эталоном — кликабельным прототипом.
- **Размеры:** 1 pt из токенов = 1 единица UI. Canvas Scaler: Scale With Screen Size, эталон **390 × 844**, Match = 0 (по ширине — у нас колонка с полями 20 pt). Проверить на 320 × 568 и 430 × 932 (кадры из `layout.frames`).
- **Безопасная зона:** `Screen.safeArea` для шапки и нижней кнопки.
- **Тени и скругления** (`elevation`, `radii`): в uGUI нет box-shadow — запекаем в 9-slice-спрайты для R1 = 12, R2 = 18, R3 = 28 и каждой высоты (inset / raised / floating).
- **Шрифты:** Inter и Source Serif 4 → TextMeshPro SDF. Набор символов — латиница + кириллица; остальное по решению о языках.
- **Фактура бумаги** (`texture`): тайловая текстура поверх `paper` и `panel`, прозрачность из токена, проверить на телефонах (там же описана приёмка).
- **Движение** (`motion`, `reducedMotion`): длительности и кривые — из токенов; при уменьшенном движении в системе выключать параллакс и покачивания.

## 7. Данные и сохранение

- Модель письма — без изменений (`CONCEPT.md` §8: `letter_date`, задачи с `game_id`/`level_id`/`seed`/`elapsed`, оформление, `sent_at`, поля соцслоя на будущее).
- Сохранение — JSON в `Application.persistentDataPath`, запись атомарная (во временный файл, потом замена) + предыдущая копия. Это закрывает SYS-04 (восстановлен) и SYS-05 (ошибка сохранения).
- Экспорт прогресса (SET-02) — файл через системное меню «Поделиться».
- Дата письма — по локальному времени устройства, правило полуночи — как в §8 концепции. Защиту от перевода часов в MVP не делаем.
- Обновление: код — через стор; баннер SYS-06 нужен только если появится загрузка контента без обновления (Addressables).

## 8. Платформа

- **Заставка (SYS-01):** нативный launch screen — фон `paper` `#F7F2E9` и знак приложения; затем сцена комнаты. Экран «Несём письмо…» (SYS-02) — только если загрузка дольше 300 мс.
- **Уведомления:** спрашиваем после первой отправки (решение автора не меняется). На iOS — системный запрос, на Android 13+ — разрешение `POST_NOTIFICATIONS`. Одно напоминание в день, когда пришло письмо.
- **Аналитика** (`CONCEPT.md` §10) — провайдер не выбран. Если не отслеживаем между приложениями, на iOS запрос ATT не нужен.
- **Возрастной рейтинг** — тёмная история (`CONCEPT.md` §3.5) влияет на анкеты App Store и Google Play; заполнить по библии мира.

## 9. Хаптика

Таблица `haptics` в токенах остаётся источником. Реализация: iOS — Core Haptics / UIFeedbackGenerator через нативный плагин, Android — `VibrationEffect`. Пометка в токенах «на iPhone в PWA хаптики не будет» для Unity неактуальна.

## 10. Арт под Unity

Всё — в `design/ROOM-ART-BRIEF.md` §11. Коротко: PNG @3x, **Pixels Per Unit = 3** (1 единица = 1 pt), ортографическая камера size 422 (половина 844), значит комната масштабируется по высоте экрана ровно как в ТЗ; Sprite Atlas на зону; фон режем на тайлы не больше 2048 px.

## 11. Что делать первым

1. Экспорт уровней трёх игр в JSON + golden-последовательности ходов (в `stazzi`).
2. Пустой Unity-проект со структурой §5, CI-сборка Android и iOS.
3. Порт движка The Gap (самый маленький, 207 строк) + golden tests — проверка процесса.
4. Комната на плейсхолдерах (референс `design/refs/room-mood-v0.png`) — камера с 3 точками, главная кнопка.
5. Петля одного дня: письмо → задача → марка → конверт → отправка → записка.
